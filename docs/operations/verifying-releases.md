# Verifying releases

Every repo-guardian artefact is signed and carries provenance you can
check before you run it:

| Artefact | Where | Signed with | Provenance | SBOM |
| --- | --- | --- | --- | --- |
| Image | `ghcr.io/donaldgifford/repo-guardian` | cosign keyless | SLSA Level 3 (slsa-github-generator) | SPDX, cosign attestation |
| UI image | `ghcr.io/donaldgifford/repo-guardian-ui` | cosign keyless | SLSA Level 3 | SPDX, cosign attestation |
| Chart | `oci://ghcr.io/donaldgifford/charts/repo-guardian` | cosign keyless | SLSA Level 3 | SPDX, cosign attestation |
| Binaries | GitHub release assets | GPG over `checksums.txt` | none yet | SPDX `*.sbom.json` beside each archive |

Images are tagged without the `v` (`2.0.0`), git tags and releases
with it (`v2.0.0`). The ECR mirror, where enabled, carries the same
signatures under its own registry path.

## What you need

- [cosign](https://docs.sigstore.dev/cosign/system_config/installation/) v2 or v3.
- [slsa-verifier](https://github.com/slsa-framework/slsa-verifier) for
  the alternative provenance check.
- `gpg` and `sha256sum` (or `shasum -a 256`) for the binaries.

Verify by digest where you can: a tag can be moved, a digest cannot.
`docker buildx imagetools inspect <image>:<tag>` prints it.

## The signing identity

The images and the chart are signed and their SBOMs attested by the
publish workflows through GitHub's OIDC token, so the certificate's
identity is the workflow file and the ref it ran from:

- a release from `main` runs `ghcr.yml` as a reusable workflow of
  `release.yml`, so the identity is
  `https://github.com/donaldgifford/repo-guardian/.github/workflows/ghcr.yml@refs/heads/main`;
- a hand-published release candidate runs `ghcr.yml` from its tag:
  `https://github.com/donaldgifford/repo-guardian/.github/workflows/ghcr.yml@refs/tags/v2.0.0-rc.18`.

The commands below match either with one expression. Pin the exact
identity instead when you know how the version was published. The
issuer is always `https://token.actions.githubusercontent.com`.

```bash
ID='^https://github\.com/donaldgifford/repo-guardian/\.github/workflows/(ghcr|ecr)\.yml@refs/(heads/main|tags/v.+)$'
ISSUER='https://token.actions.githubusercontent.com'
```

## Signatures

```bash
cosign verify --certificate-identity-regexp "$ID" --certificate-oidc-issuer "$ISSUER" \
  ghcr.io/donaldgifford/repo-guardian:2.0.0

cosign verify --certificate-identity-regexp "$ID" --certificate-oidc-issuer "$ISSUER" \
  ghcr.io/donaldgifford/repo-guardian-ui:2.0.0

cosign verify --certificate-identity-regexp "$ID" --certificate-oidc-issuer "$ISSUER" \
  ghcr.io/donaldgifford/charts/repo-guardian:2.0.0
```

A pass prints the verified payload as JSON. Any other identity, or none,
is a failure.

## SLSA provenance

Provenance is written by the
[SLSA GitHub generator](https://github.com/slsa-framework/slsa-github-generator),
so its identity is the generator's workflow, not ours:

```bash
cosign verify-attestation --type slsaprovenance \
  --new-bundle-format=false \
  --certificate-identity-regexp '^https://github\.com/slsa-framework/slsa-github-generator/.+' \
  --certificate-oidc-issuer "$ISSUER" \
  ghcr.io/donaldgifford/repo-guardian:2.0.0
```

Swap the reference for the UI image or the chart. `--new-bundle-format=false`
is needed on cosign v3: it reads only new-bundle referrers by default,
the generator writes the legacy `.att` tag, and without the flag cosign
reports a misleading identity mismatch against our own signature.

`slsa-verifier` checks the same provenance against the source
repository and tag:

```bash
slsa-verifier verify-image \
  ghcr.io/donaldgifford/repo-guardian@sha256:<digest> \
  --source-uri github.com/donaldgifford/repo-guardian \
  --source-tag v2.0.0
```

The provenance records the workflow, the source commit and the builder,
which is what an admission policy can enforce.

## SBOMs

Each image and the chart carries an SPDX SBOM as a cosign attestation,
generated by syft over the published digest:

```bash
cosign verify-attestation --type spdxjson \
  --certificate-identity-regexp "$ID" --certificate-oidc-issuer "$ISSUER" \
  ghcr.io/donaldgifford/repo-guardian:2.0.0 > /dev/null
```

To read it:

```bash
cosign download attestation --predicate-type https://spdx.dev/Document \
  ghcr.io/donaldgifford/repo-guardian:2.0.0 \
  | jq -r '.payload' | base64 -d | jq '.predicate'
```

The images' buildkit attestations (`docker buildx imagetools inspect
--format '{{ json .SBOM }}'`) carry a second SBOM from the build
itself; the cosign attestation is the one signed by our identity.

## Binaries

Each GitHub release has the archives, an SPDX SBOM per archive
(`*.sbom.json`), `checksums.txt` covering both, and `checksums.txt.sig`,
a detached GPG signature by the release key:

```text
C47D 59D8 6FC2 4BAE C5BB  3271 2E2C EA0B C2BD 8D59
```

```bash
gpg --verify checksums.txt.sig checksums.txt
sha256sum --ignore-missing -c checksums.txt
```

Check that `gpg` reports a good signature from that fingerprint, then
that every file you downloaded is `OK`. IMPL-0036 replaces the GPG
signature with cosign and SLSA provenance for the binaries, like the
images.
