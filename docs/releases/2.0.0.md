# repo-guardian 2.0.0

> [!IMPORTANT]
> **2.0.0 is a fresh install, and `latest` now points at it.** It does
> not read a 1.x `guardian.hcl`, the 2.x chart refuses every 1.x value
> at render time, and the database schema is new. Anyone pulling
> `ghcr.io/donaldgifford/repo-guardian:latest` gets 2.0.0 from this
> release on: pin `1.14.1` to stay on 1.x. The chart defaults its image
> tag to its `appVersion`, so chart users are unaffected unless they set
> `image.tag: latest`.

## What 2.0 is

repo-guardian evaluates every repository in your GitHub organisations
against a policy you keep as code, records who is compliant with which
control and why not, and, where the policy says so, fixes it.

- **Controls, not rules.** The policy is a directory: `enterprise.hcl`
  names the organisations and the baseline, `catalogue/` defines
  versioned controls (`codeowners@1`), `orgs/` adds per-org controls,
  exclusions and overrides, `templates/` overrides the embedded files.
  Eight built-in control types cover files and the GitHub API. See the
  [policy reference](../usage/policy-reference.md) and the
  [control-type reference](../usage/controls-reference.md).
- **Two GitHub Apps.** The Evaluation App reads everything; the
  Remediation App writes, only where you install it. Each is held by
  its own role, with its own key.
- **Remediation you opt into.** Only an assignment in
  `mode = "remediate"` writes: one pull request per control on a
  `repo-guardian/<control>` branch, or a direct API change. It never
  force-pushes and never deletes a branch.
- **Temporal and Postgres.** Every repository has its own durable
  evaluation workflow, with a rate budget per installation per App.
  Results and their history live in Postgres behind per-role database
  users that can each write only their own columns.
- **A business UI and a read-only API.** Compliance by control and org,
  findings with their evidence, remediations and holds, and history,
  without PromQL, behind your identity provider.

## Installing

Follow [Getting started](../usage/getting-started.md), then
[Turning on repo-guardian v2](../operations/v2-onboarding.md):

```bash
helm install repo-guardian oci://ghcr.io/donaldgifford/charts/repo-guardian \
  --version 2.0.0 --namespace repo-guardian --create-namespace -f values.yaml
```

Moving from 1.x: [Migrating from v1 to v2](../operations/v2-migration.md)
lists every removed variable and value with its replacement, and
[rgctl](../operations/rgctl.md) finds and closes the pull requests 1.x
opened.

## Identity providers

The API and UI work with Keycloak, Okta, Entra ID and Auth0 without code
changes; [Identity providers](../operations/identity-provider.md) has a
recipe and a sign-in check for each.

## Verifying this release

The images, the UI image and the chart are signed with cosign
(keyless) and carry SLSA Level 3 provenance and an SPDX SBOM
attestation; the binaries ship an SPDX SBOM per archive and a
GPG-signed `checksums.txt`. The commands are in
[Verifying releases](../operations/verifying-releases.md).

## Supported versions

2.x is supported. 1.14.x receives security fixes for 90 days after
2.0.0; see [SECURITY.md](https://github.com/donaldgifford/repo-guardian/blob/main/SECURITY.md).
