    Overview

    The v2 business UI shipped in IMPL-0025 Phases 20 to 22 with shadcn's default light palette, a text-link header, native <select> filters and a single line chart. It works, and it looks like a scaffold. Two source mockups informed what it should become. A sizzle reel settled the look: one dark charcoal theme, a mono-and-sans type pairing, 3px radii, filled tinted badges, dense tables. A platform mockup contributed layout ideas: an icon sidebar with grouped entries and counts, a page header with breadcrumbs and range controls, a compliance card that puts the KPIs and the trend in one frame, sparklines in the rules table, an expandable org grid with heat-shaded cells, a two-thirds plus one-third repository page, and a draft status page.

    Neither source is kept. Their decisions are folded into one artifact, ui/design/repo-guardian-mockup.html: a single self-contained page, no build step and no network, that renders every route of the redesigned UI from an in-page fake of today's read-only API. Every number on it comes from a field api/openapi.yaml serves now; a panel that would need a field the API lacks renders as a one-line "deferred" note naming the open question, so the gap is visible instead of drawn over. "The mockup" below means that file. This document is the specification; the mockup is the picture of it, and the two are kept in step.

    This design takes the look from the reel, the layouts from the platform mockup where they survive contact with real data, maps every panel to the field behind it, and names the handful of places where a panel needs a field the API does not have. The status page, which both sources treated as an afterthought, gets a proper design here because it is the one public surface and today's version is a list.

    Goals and Non-Goals

    Goals

    • One theme, declared once as Tailwind v4 @theme tokens taken from the sizzle, so components stop carrying their own colours.
    • A shell worth the name: icon sidebar with groups and counts, a top bar with search, time zone and account, breadcrumbs, and a consistent page header with the scope and range controls on the right.
    • Fleet, Rules, Orgs, Findings and Repository re-laid out on the platform mockup's patterns, each panel wired to a real API field.
    • A findings detail drawer with badges, evidence and a timeline, deep linkable, so "what is wrong and what was done" is a click.
    • A designed public status page: a state banner, components, fleet compliance with a sparkline, and nothing that names a repository.
    • Keep every security property DESIGN-0027 established: text-only evidence, links built from structured fields, no inline scripts, no external origins, a GET-only proxy.
    • Build the table, grid, drawer and chip components generically so the IMPL-0029 Controls views reuse them.

    Non-Goals

    • No write path. The drawer gets an empty actions slot for IMPL-0029's re-evaluate button; this design adds no POST.
    • No light theme in this change. Tokens make it a later swap (OQ1).
    • No portal chrome. The platform mockup is a multi-app shell (app switcher, notifications bell, favourites). Repo Guardian ships alone; the shell is built so it can later sit inside that portal, but the switcher and the bell are not drawn.
    • No "compliance drivers" map. The mockup's initiatives → inputs → KPIs flow has no data behind it and no owner.
    • No BFF, session, OIDC or CSP changes beyond one optional config value for the documentation link. Where the CSP constrains the design (fonts, images) the design bends, not the CSP.
    • No Grafana, operator or system dashboards; those stay generated (DESIGN-0022).
    • No new tables or migrations. API additions are small, additive, and listed in one place.

    Background

    What the UI is today

    ui/web/src/router.tsx renders a top header with a wordmark, horizontal text links (Fleet, Rules, Orgs, Findings, History, Policy), a native <select> org filter written to ?org=, the user's name as text and a POST sign-out button. There is no sidebar. index.css holds a light-only shadcn neutral palette in oklch plus four status colours; there is no dark mode and no font declaration. components/ui/ has Badge (five tones), Button, Card and Table. components/common.tsx has StatusBadge, ExternalLink, Evidence, Remediation, Tile, Section, Loading, Empty and TrendChart, the only Recharts use.

    Fleet is four tiles, the 90d line chart, open-PR buckets as text, the worst five rules as a link list and parked-by-reason as text. Findings is native selects over a six-column table with Load-more and CSV export; there is no row detail. Repository has the only timeline and the recent-checks list. History is one small chart per org. Policy is tiles and a table. The public status page is a component list.

    Two sources, two jobs

    Concern Taken from Not taken

    Sidebar structure (groups, icons, counts), top bar controls, breadcrumbs, page header with scope and range platform mockup app switcher, bell, favourites
    Fleet layout: combined compliance card, PR-age bars with threshold link, finding-age distribution, worst rules, parked-by-reason bar list, findings-by-status bar, by-rule and by-org tables platform mockup drivers map, PR throughput (no endpoint yet, OQ15), donuts (replaced by bar lists, see Charts)
    Rules: kind tabs, KPIs, stacked bar, table; rule detail with per-org bars, top-reasons bar list, oldest failures platform mockup
    Orgs: expandable grid, heat-shaded cells, tabs, totals row, export platform mockup repository-level rows under an org (OQ13)
    Findings table and detail drawer, evidence block, timeline sizzle reel (drawer), mockup (filter bar and result count) the reel's sort = pr_age chip until the API sorts

    The synthesis, and the thing to open when a sentence below is unclear, is ui/design/repo-guardian-mockup.html. It is deliberately built with hand-written CSS and SVG rather than the SPA's stack so that it stays a design document: the implementation copies its tokens, layouts and chart rules into Tailwind, React and Recharts, not its code. Its fake API (api.* in the script) mirrors the operation set and field names of api/openapi.yaml, so a mockup panel that reads a field the schema lacks is a bug in the mockup, not a proposal.

    The reel's application frame uses the sans face for page titles and the drawer; its display face (Bricolage Grotesque) appears only in the marketing scenes. The app ships two families, not three.

    Constraints already in force

    • CSP. ui/server/static.ts sends default-src 'self'; connect-src 'self'; frame-ancestors 'none'; script-src 'self'. With no font-src, style-src or img-src, each falls back to 'self'. External fonts are blocked, and so is any data: URI Vite inlines for assets under 4 KB (assetsInlineLimit). Remote avatar images are blocked; /me carries no avatar anyway.
    • Evidence is text. ESLint bans every HTML sink; evidence.ts renders only reasons it knows. Every evidence surface in this design is a styled container around that output.
    • Links are built, never trusted. lib/pr.ts builds PR and repository URLs from host, org, name and number.
    • Org scope lives in the URL as ?org=, retained across links; the Playwright scoping test depends on it.
    • Findings have no id. Identity is (repository_id, rule_kind, rule_name). There is no /findings/{id}; events are per repository and record status transitions only; checks are per repository.
    • No server-side sort on /findings, and no aggregates beyond /summary, /rules, /orgs and /orgs/{org}.
    • History is per (org, rule) and capped client-side at 4,000 points; 90 days across six orgs and eight rules already exceeds it.
    • The status page is public and privacy-guarded. TestStatus_PrivacyGuard fails on any string field in the Status schema outside an allowlist. Anything added to it must be a number, a timestamp or an enum.

    The controls rework is coming

    IMPL-0029 task 8.7 replaces the Rules and Findings views with Controls views, Policy with /policies, and gives Repository a controls tab and an evaluation log; INV-0021 marks rules.tsx, findings.tsx and evidence.ts as rule-shaped and slated for replacement; IMPL-0030 adds a Remediations view. The durable deliverables here are the tokens, the shell, the page anatomy, the Fleet page and a set of generic components; the rule-shaped views become thin consumers so that 8.7 swaps data and columns, not chrome (OQ12).

    Detailed Design

    Design language

    One theme, dark, declared once in index.css as Tailwind v4 @theme variables. The sizzle's stage tokens map as follows.

    Token Value Reel source Used for
    --color-background #17191d --st-bg page, evidence block, inset panels
    --color-panel #1f2227 --st-panel cards, top bar, sidebar, drawer
    --color-panel-2 #262a30 --st-panel2 current nav item, selected tab, meter track, hover rows
    --color-border #31363d --st-line every 1px rule and border
    --color-foreground #e8eaed --st-fg text
    --color-muted-foreground #9aa1ab --st-muted labels, sublines, inactive nav
    --color-accent #5fa8f5 --st-accent links, brand mark, primary series, current timeline node, focus ring
    --color-ok #3fb950 --ok compliant, applied, operational
    --color-warn #d9a020 --warn foreign_pr, degraded, reason badges, unknown
    --color-bad #f2554d --bad non_compliant, failing, down
    --color-info #7aa7ff --info pr_open, secondary series
    --color-avatar #3a4c6d --avatar initials avatar
    --radius-lg 3px --st-radius cards, tabs, nav items, avatar, inputs

    Chart series colours are derived from the same set: accent for the primary series, info for a second, ok/warn/bad where a series means good, caution or bad, and muted-foreground for not-applicable. The mockup's categorical palette is not adopted; a chart never needs more than the five tones above plus muted.

    The existing --color-compliant, --color-non-compliant, --color-not-applicable and --color-unknown become aliases of ok, bad, muted-foreground and warn while views are converted, and are removed with the last consumer.

    Type. Sans: IBM Plex Sans 400/500/600. Mono: JetBrains Mono 400/500. Root 14px; tables, nav, chips and filters 13px; card and KPI labels 12px, uppercase with 0.06em tracking for stat-strip labels as in the mockup; KPI values 22px/600 with tabular-nums; page titles 20px/600 in the sans face. Monospace is semantic: identifiers (repository and rule names, reason codes, PR numbers, timestamps, filter values, query names in subtitles) are mono; prose is sans.

    Badges (the reel's .badge): mono 12px, 5px 7px, no radius, background color-mix(in srgb, <tone> 18%, transparent), text color-mix(in srgb, <tone> 65%, white) (75% in the first draft; IMPL-0031 6.1's axe run put the bad tone on a selected row under AA). One tone table in lib/format.ts covers every documented value, with mute for anything unknown (both enums are open):

    Field Value Tone
    status compliant ok
    status non_compliant bad
    status not_applicable mute
    status unknown warn
    remediation pr_open info
    remediation applied ok
    remediation foreign_pr warn
    remediation disabled, dry_run, none mute (none renders "—" in tables)
    reason any, in the drawer warn under non_compliant, else mute
    component state operational / degraded / anything else ok / warn / bad
    rule kind file, setting, branch_protection, … outline (border only, muted text)

    Surfaces. A card is panel, 1px border, 3px radius, a header of a 13px/600 title and a 12px muted subtitle, then a body. Cards may carry a stat strip under the header (the mockup's compliance card): a row of label-over-value cells separated by hairlines. No shadows except the drawer edge; no gradients except the chart area fill.

    Density. Tables at 13px with 9px 10px cells and hairline rows; numeric columns right-aligned tabular; a hover tint of panel-2; a selected row tinted accent at 12%.

    Motion. None of the reel's entrance animations ship. Drawer slide and popover fades at 200ms, off under prefers-reduced-motion.

    Fonts under the CSP

    Fonts are bundled: @fontsource/ibm-plex-sans (latin, 400/500/600) and @fontsource/jetbrains-mono (latin, 400/500), imported from main.tsx so Vite emits hashed woff2 files under /assets/, which the BFF already caches for a year. build.assetsInlineLimit: 0 keeps every asset a file rather than a data: URI, and a build test fails if dist/ contains a data: URL or a fonts.googleapis.com reference. font-display: swap. Both families are SIL OFL; licences ship with the other third-party notices. The CSP does not change (OQ2).

    Shell

    The frame is a 40px top bar over a two-column body: a 220px sidebar (the mockup's width, a little wider than the reel's 196px to fit icons and counts) and a scrolling main area. Both bars are panel on a background page.

    Top bar, left to right:

    • Brand: the shield mark in accent, "Repo Guardian" in foreground 600, and the mockup's muted qualifier compliance · read-only. The brand links to /. There is no app switcher; the slot to the left of the brand is reserved so a portal can add one later.
    • Right: a search button labelled ⌘K that opens the command palette; a time-zone control; the avatar.

    Command palette (⌘K / Ctrl-K): a dialog with one input that searches repositories through GET /repositories?q= (name prefix, scoped by ?org=), and matches rules and orgs from the already-loaded /rules and /orgs lists. Results are grouped (Repositories, Rules, Orgs); Enter navigates. It is the primary way to reach a repository page and replaces the mockup's placeholder "Repository (example)" nav entry (OQ11).

    Time zone. Timestamps render in the browser's zone by default. The control toggles Local / UTC, persisted in localStorage, and every timestamp goes through one formatTime helper that honours it. Hovering a timestamp shows the other zone.

    Avatar: a 20px avatar-coloured square with initials from me.name (first letters of the first two words, else the first two characters of subject). It opens a menu with the display name, the subject in mono, the docs link when configured, and Sign out, which stays a POST form to /auth/logout so the BFF's Origin check keeps working.

    Sidebar: groups with 10.5px uppercase tracked labels, each entry an icon, a label and an optional right-aligned mono count.

    • BUSINESS: Fleet (grid icon), Rules (list), Orgs (boxes), Findings (activity, count = summary.findings.non_compliant).
    • PUBLIC: Status page (check).
    • DOCS: Documentation (book), shown only when the BFF's /ui/config carries a docs_url (new optional UI_DOCS_URL env; the one BFF change in this design).

    The current item is panel-2 with foreground text and an accent left rule; others are muted-foreground. The nav is one array (label, to, icon, group, optional count selector) so IMPL-0029 renames entries by editing data. A footer line in 11px mono shows the policy version prefix and rollout state from /policy and links to /policy (OQ4). Below 900px the sidebar collapses behind a top-bar button.

    Org scope is a page-header control (below), not a top-bar one: the mockup places it beside the range control, and that is where the eye looks for "what am I looking at". It writes ?org= exactly as today; the label is All orgs (N) where N is orgs.items.length when me.all_orgs, else me.orgs.length.

    Page anatomy

    Every authenticated page uses the same header block:

    1. Breadcrumbs in 12px: Repo Guardian / <Section> [/ <item>], derived from the route (and the drawer state on Findings).
    2. Title at 20px/600, with an optional outline badge after it (a rule's kind, org, active/parked).
    3. A one-line muted subtitle that says what the page measures, in plain words, naming the endpoint in mono where the mockup did ("Fleet compliance % from /compliance/history").
    4. Right-aligned controls: the org scope popover; where the page has a time dimension, a segmented range 1d | 7d | 30d | 90d; page actions as outline buttons (Export, Findings for this rule).

    Range and scope are URL state (?range=, ?org=), so every page is a shareable link and the browser back button works.

    Fleet

    The mockup's layout, top to bottom, with the data behind each panel.

    Compliance card (two-thirds width). Title Compliance (<range>), subtitle "Fleet compliance % from /compliance/history; compliant ÷ (compliant + non_compliant) over active repositories." Then:

    • A stat strip of five cells: Tracked (summary.tracked repos), Compliant (summary.compliant_percent with a delta against the previous snapshot), Failing (summary.findings.non_compliant and the number of rules with any failure from /rules), Parked (sum of summary.parked[].count and the number of reasons), Snapshots (point count in range and the cadence word derived from the median gap between points). A null percent reads "unmeasured", never 100%.
    • Legend pills for the four series the history points carry: compliant %, failing findings, not applicable, unknown. The pills are a radio group: exactly one series is drawn at a time and the y axis rescales to it. There is no right axis and never two scales in one frame; a reader who wants two series side by side opens History, where each gets its own small chart. The pill shows the series' current value, so the strip, the pills and the chart agree by construction. Pills are buttons with role="radio" and aria-checked.

    Charts

    Recharts stays (DESIGN-0027 fixed shadcn charts). Five chart components: TrendChart (area, one series at a time), BarBuckets (single series bars), StackedBars (per-category stacked status counts, plain elements), BarList (ranked rows with count, share and a single-colour bar), Sparkline (20-point line, no axes). Meter and DistBar are plain elements. All read colours from the theme variables, use the mono face for axes at 11px, draw solid hairline grid lines in border, and ship an accessible alternative: an aria-label summary and a table toggle in the card header that swaps the plot for the same data as a dense table.

    The rules the mockup follows, which the implementation keeps:

    • One axis per chart. Two measures of different scale get two charts (History's small multiples), never a second y axis.
    • No categorical palette. The theme's accent and info are too close to tell apart for a colour-vision-deficient reader (an OKLab distance of about 3, against a floor of 8), so no chart asks a reader to separate series by hue. Magnitude is drawn in accent; status in the four status tones, and nowhere else; shares as ranked bar lists rather than donuts, where the label does the identifying.
    • Marks. Lines 2px with a 4.5px end dot ringed in the panel colour; area wash at 10% opacity; bars at most 24px wide with a 4px rounded data end; 2px surface gaps between stacked segments; the end-of-line value is the one direct label, never a number on every point.
    • Hover by default. Line and area charts get a crosshair and a tooltip, bars and cells a per-mark tooltip; hit targets are the full column, not the mark.
    • Percent axes never start at zero when the series lives in a narrow band, and a nice floor and ceiling bracket the data so the trend is legible; the end label states the current value.
    • Bar lists are sorted descending, show count and share, and never carry more than eight rows; the rest fold into "other".

    Surviving the controls rework

    • DataTable, GroupGrid, DetailDrawer, FilterChips, Timeline, Kpi, StatStrip and the charts know nothing about rules or findings. They take column specs, row keys and render props.
    • findings.tsx and rules.tsx become column specs, filter specs and a drawer body. The Controls views are other specs against other endpoints.
    • evidence.ts is untouched except for its container; INV-0021 replaces its renderers, not this design.
    • The sidebar nav is an array; renaming Rules to Controls and Findings to Evaluations is a two-line edit and the count moves with the entry.
    • The drawer's actions slot is where 8.7's re-evaluate button lands, so the BFF's eventual POST route needs no layout change.

    Accessibility

    • Contrast against the actual hex values: muted-foreground on panel 6.1:1, foreground on background 14.6:1, every badge tone at 65% toward white on an 18% tint clears 5:1. Heat-shaded cells keep their text in foreground and never rely on the shade alone (the number and the percent are printed). @axe-core/playwright runs on Fleet, Orgs, Findings with the drawer open, Repository and Status.
    • Focus is a 2px accent ring with 2px offset on every interactive element, including table rows and legend pills.
    • The drawer and the palette are dialogs: labelled, focus-trapped, Escape closes, focus returns.
    • Charts carry text alternatives; colour is never the only signal (badges carry text, deltas carry arrows, meters print the percent, distribution segments have a legend).
    • No motion beyond drawer and popovers, none under prefers-reduced-motion.
