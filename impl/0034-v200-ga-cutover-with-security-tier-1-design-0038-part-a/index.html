    Objective

    Take v2 to main and ship v2.0.0 through the existing release pipeline: converge the branches with merge commits, make the tree GA-shaped before the final merge (docs, changelogs, branch-entry reverts, chart 2.0.0), land the first tier of supply-chain security (SBOMs, CodeQL, rulesets, pins, pod hardening, a verification page), run the soak IMPL-0030 set, then merge with the major label so one push produces the binaries, both registries, the UI image, the chart and provenance.

    Implements: DESIGN-0038 Part A (A1–A9), Part D tier 1 (D4), decisions D1–D3, D10–D12, OQ1–OQ3, OQ10–OQ12, OQ16–OQ19. Supersedes IMPL-0030 OQ12 and carries IMPL-0030 Phase 10.

    Scope

    In Scope

    • M1 (main → v2) and M2 (v2 → main), both merge commits through pull requests; M2 labelled major.
    • mkdocs-ghpages.yml inheriting mkdocs.yml, a strict docs build in CI, the nav reorganised, mermaid rendering in the interim (OQ1).
    • The documentation rewrite inventory from DESIGN-0038 A4, the v2-migration.md contradictions, the historical admonitions.
    • changelog-update.yml prepending; the [main, v2] trigger reverts; ct.yaml; prerelease.yml and changelog-update.yml wording; CLAUDE.md § The v2 branch and rule 6; CONTRIBUTING.
    • Security tier 1: SBOM generation and attestation for binaries, both images and the chart; CodeQL default setup; required status checks and a v* tag ruleset; @latest pins; Dependabot/Renovate clean-up; chart security-context parity; verifying-releases.md; SECURITY.md; concurrency and release.yml permission narrowing.
    • Chart 2.0.0, the 2.0.0 UI changelog entry, regenerated READMEs.
    • The soak gate and the homelab tasks gathered from IMPL-0029/0030/ 0031/0032, ticked here and there.
    • Post-GA bookkeeping: docz statuses, issues, memory, the v2 branch.

    Out of Scope

    • Security tiers 2–3 (IMPL-0036) and the Astro docs site (IMPL-0035).
    • Any runtime behaviour change. Every code edit in this IMPL is to workflows, chart defaults, docs or metadata.
    • An in-place upgrade from 1.x (DESIGN-0032 D27).
    • IMPL-0026, DESIGN-0034, the Go module path (OQ11 decided).

    How the phases are ordered

    Phase 1 first because every later edit must land on a tree that is a superset of main. Phases 2–5 are independent of one another and of the soak; they are separate pull requests against v2, each reviewable alone and none changing runtime behaviour. Phase 6 is the last pull request before M2 and makes the tree GA-shaped. Phase 7 runs in the homelab in parallel with 2–6 and is the clock. Phase 8 is M2 and the release; Phase 9 the clean-up. IMPL-0033 (rc.17) merges before Phase 6 so the GA docs name knobs that exist.
