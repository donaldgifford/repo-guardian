    Objective

    Rebuild the look and layout of the v2 business UI and the public status page to DESIGN-0036: one dark theme declared once as Tailwind tokens, bundled fonts under the unchanged CSP, a shell with an icon sidebar, top bar, breadcrumbs and a shared page header, the Fleet, Rules, Orgs, Findings and Repository pages re-laid out on the data the read-only API serves today, a findings detail drawer with evidence and a timeline, a designed status page, and a set of generic table, grid, drawer, chip and chart components that IMPL-0029 task 8.7 builds the Controls views on. The last code phase adds the five small, additive API fields the design names, each un-hiding one panel.

    The picture of the result is ui/design/repo-guardian-mockup.html. Every task below that says "as the mockup draws it" means that file's route; where the mockup and this plan disagree, DESIGN-0036 wins and the mockup is fixed in the same change.

    Implements: DESIGN-0036 (all sections; Open Questions taken at their ✅ recommendations unless the Open Questions below say otherwise), the UI consequences of DESIGN-0027 §The UI, and the additive API changes listed in DESIGN-0036 §API / Interface Changes.

    Scope

    In Scope

    • ui/web/src/index.css tokens, fontsource fonts, the Vite inline limit and a build guard over dist/.
    • The primitive and chart set in ui/web/src/components/ui/ and components/charts/, the badge tone table, formatTime with the Local/UTC toggle.
    • The shell (router.tsx → components/shell/): top bar, sidebar from a nav array, breadcrumbs, page header, org scope popover, range tabs, command palette, avatar menu, collapsed sidebar under 900px.
    • Fleet, Rules, rule detail, Orgs grid, org detail, Findings with the drawer, Repository, History and Policy restyles, and the status page.
    • The one BFF change (UI_DOCS_URL → docs_url in /ui/config) and the matching chart value ui.docsUrl.
    • Unit, component, build-guard, Playwright, axe and screenshot tests; updates to docs/usage/ui.md, ui/README.md and CLAUDE.md.
    • Five additive API changes, each with its sqlc query, handler, apitest case, regenerated server and client, and the UI panel it un-hides: aggregate= on /compliance/history, sort= on /findings, Summary.finding_age[], Status.compliance.history[] plus Status.operations, and OrgSummary.open_prs.

    Out of Scope

    • Any write path. The drawer's actions slot stays empty; no POST route is added to the BFF (IMPL-0029 8.7 owns re-evaluate).
    • A light theme, a portal shell (app switcher, bell), the "compliance drivers" map, the PR throughput card (DESIGN-0036 OQ15, deferred), a standalone /repos list (OQ11).
    • CSP, session, OIDC or proxy changes. The CSP string in ui/server/static.ts does not change.
    • Database tables or migrations. Every API addition is a query over existing columns.
    • Replacing lib/evidence.ts renderers (INV-0021 / IMPL-0029) or the Controls, Remediations and /policies views (IMPL-0029, IMPL-0030).
    • Grafana dashboards and alerts (DESIGN-0022, generated).

    How the phases are ordered

    Phases 1 to 7 are code, each ending with make lint-ui, make test-ui and, from Phase 2 on, make test-ui-e2e green, with a commit per numbered task. Phase 1 is tokens, fonts and the component and chart set, so every page after it is composition. Phase 2 is the shell and the page anatomy; it is the phase that moves Playwright selectors, so the e2e suite is repaired here once. Phases 3 and 4 are the pages, in the order the design's rollout plan gives: Fleet and Rules first because they exercise every chart, then the three table-shaped pages and the drawer, which produce the generic DataTable, GroupGrid, DetailDrawer and FilterChips that IMPL-0029 reuses. Phase 5 is the status page, isolated because it is public and privacy-guarded. Phase 6 is accessibility, screenshots, docs and the removal of what the restyle made dead. Phase 7 is Go: the five API additions, each its own task, each un-hiding a panel that Phases 3 to 5 built hidden. Phase 8 is human-run: the rc image, the homelab deploy and the review of the pages against the mockup.

    The plan lands as one PR into v2 with the dont-release label (OQ1) and must merge before IMPL-0029 task 8.7 starts (DESIGN-0036 OQ12). Phase 8 is deferred - human required.
