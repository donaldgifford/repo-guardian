<!--docz:objective:start-->
## Objective

Replace the MkDocs public site on GitHub Pages with an Astro Starlight
site built from the same `docs/` tree, deployed through GitHub's Pages
Actions flow, with link validation, mermaid rendered in the browser,
search, and a sidebar that follows the directory layout. The shape
follows `donaldgifford/claudelint`'s working Starlight setup
(DESIGN-0003 there): `site/` beside `docs/`, a symlinked content
collection, an in-repo remark link rewriter, autogenerated sidebar
groups per docz directory. TechDocs keeps reading
`mkdocs.yml`; nothing in `docs/` is rewritten for one renderer at the
other's expense.

**Implements:** [DESIGN-0038](../design/0038-v200-ga-cutover-and-identity-provider-portability.md)
Part C (C1–C5), D5–D8, OQ13–OQ15. Replaces IMPL-0034 Phase 2's interim
site.

<!--docz:objective:end-->

<!--docz:scope:start-->
## Scope

<!--docz:in-scope:start-->
### In Scope

- `site/`: Astro + Starlight, bun-managed, pinned, with the `docs/`
  content collection, a remark link rewrite, `starlight-links-validator`,
  client-side mermaid, Pagefind search.
- Frontmatter `title` on the 35 pages that lack it, including the
  generated `controls-reference.md` through `WriteReference`.
- The sidebar (autogenerated by directory, a hand-listed "Historical
  (1.x)" group), the landing page, the DESIGN-0036 tokens.
- Replacing the `docs` CI job's MkDocs build with the Starlight build,
  `astro check` and a static check over `dist/`; `gh-pages.yml` → Pages
  Actions deploy. No browser in the docs build (OQ1 (b)).
- Deleting `mkdocs-ghpages.yml`, the `gh-pages` branch and the pip
  install; CLAUDE.md, CONTRIBUTING and README updates.

<!--docz:in-scope:end-->

<!--docz:out-of-scope:start-->
### Out of Scope

- Removing `mkdocs.yml` or `techdocs-core` (TechDocs).
- Rewriting document bodies beyond frontmatter, one admonition and the
  TOC blocks (OQ2).
- Versioned docs (one site, the current line; 1.x pages are the
  Historical group).
- Building the UI's `ui/` and `site/` as one workspace.

<!--docz:out-of-scope:end-->
<!--docz:scope:end-->

## Pre-implementation audit

Verified 2026-10-25:

- 126 markdown files under `docs/`; 80 carry a docz `<!--toc:start-->`
  block; 473 relative `.md` links (DESIGN-0038 C2). 35 files have no
  frontmatter `title`: every docz section `README.md`, `docs/index.md`,
  `docs/ADDING_RULES.md`, all `docs/operations/*.md` and `docs/usage/*.md`.
  `docs/usage/controls-reference.md` is generated by `repo-guardian
  controls docs` (`internal/controls/builtin/reference.go`
  `WriteReference`, header `# Control-type reference`) and gated by `make
  lint-controls-docs`, so its frontmatter must come from the generator.
- Three MkDocs `!!! note "v1 only"` admonitions, all in
  `docs/operations/migrations.md` (lines 67, 327, 414); the remaining
  pages use plain blockquotes.
- 39 mermaid fences in 15 docs (DESIGN-0038 § Background).
- Mermaid diagrams, docz TOC blocks and relative links all render on
  TechDocs today; TechDocs must keep working unchanged (D5).
- `mise.toml` pins `bun = "1.3.14"` with a renovate comment; `ui/`
  uses bun with `bun.lock`; Renovate's `npm` manager is enabled by the
  shared presets, so `site/package.json` is picked up with no config
  change.
- `.github/workflows/gh-pages.yml` runs `mkdocs gh-deploy --config-file
  mkdocs-ghpages.yml --force` to the `gh-pages` branch; Pages is set to
  deploy from that branch (legacy source). `actions/configure-pages`,
  `upload-pages-artifact` and `deploy-pages` need the `pages: write` and
  `id-token: write` permissions and the Pages source set to "GitHub
  Actions".
- The `docs` paths filter and job exist from IMPL-0034 Phase 2 (MkDocs
  strict build); `make lint-docs` wraps it.
- **claudelint's setup (read 2026-10-25, `site/` on `main`)**, the
  reference for this IMPL: `site/src/content/docs` is a `120000`
  symlink to `../../../docs` because Starlight's `docsLoader()`
  hard-codes `src/content/docs/` and its autogenerate filter strips
  that prefix (a bare `glob({base: '../docs'})` serves pages but every
  autogenerated group renders empty); `docsSchema` is extended with
  docz's `id`/`status`/`author`/`created` as optional fields;
  `site/src/plugins/remark-md-link-rewriter.mjs` (unist-util-visit,
  ~60 lines) rewrites relative `.md` links to lowercase absolute routes
  and leaves out-of-tree links alone; docz READMEs carry frontmatter
  (`title`, `sidebar: {order: 0, label: Overview}`) that `docz update`
  preserves, and render at `/<type>/readme/`; `docs.yml` runs
  `npm run check` (`astro check`) + `astro build` and uploads `dist/`
  `if: always()`; `lint-md` greps `docs/` for `!!!`/`???` admonitions
  and `pymdownx` so the shared source stays CommonMark+GFM; GFM alerts
  (`> [!NOTE]`) replaced admonitions. Two differences to keep: it uses
  npm with a pinned Node and caret ranges (we use bun and exact pins),
  and it deploys to Cloudflare Pages with PR previews (we stay on
  GitHub Pages, OQ5). Mermaid is wired in neither of its pipelines.
- **MkDocs `site_dir` collision.** MkDocs's default output directory is
  `site/`, and `.gitignore` line 46 ignores `site/`; IMPL-0034 2.5 moves
  the build to `build/mkdocs` and narrows the ignore before this IMPL
  creates `site/` (verify in 1.1).

## How the phases are ordered

Phase 1 produces a building site from the unmodified tree so every
later change is measured against a green build. Phase 2 makes the
content render correctly (titles, links, diagrams, admonition, TOC
blocks) and adds the validators that keep it so. Phase 3 shapes the
sidebar, Phase 4 the look. Phase 5 wires CI before anything deploys, so
Phase 6 switches the Pages source once with the build already proven
on pull requests.

## Implementation Phases

Each phase builds on the previous one. A phase is complete when all its
tasks are checked off and its success criteria are met.

### Phase 2: Markdown compatibility

DESIGN-0038 C2, D6, D7; IMPL-0035 OQ1, OQ2, OQ6.

<!--docz:tasks:start-->
#### Tasks

- [ ] 2.1 **Titles.** Add `---\ntitle: ...\n---` to the 34 hand-written
  pages lacking it (the title is the H1 text); keep the H1 in the body
  so TechDocs and GitHub rendering are unchanged. Starlight renders the
  title itself, so set `markdown.remarkPlugins` to strip the first H1
  when it equals the frontmatter title (part of the in-repo plugin in
  2.3) rather than deleting the H1s.
- [ ] 2.2 **Generated reference.** `WriteReference` emits the frontmatter
  block (`title: Control-type reference`) before `# Control-type
  reference`; regenerate with `repo-guardian controls docs`;
  `TestWriteReference_*` goldens updated; `make lint-controls-docs`
  green.
- [ ] 2.3 **Link rewrite plugin.** Copy claudelint's
  `site/src/plugins/remark-md-link-rewriter.mjs` (the user's own code)
  and extend it (OQ6): keep its resolve-against-source + lowercase +
  absolute-route behaviour; add the `README.md` → directory route and
  `index.md` → `/` rules (OQ3), prefix `base` (claudelint has none),
  and turn links to files outside `docs/` (`../CLAUDE.md`,
  `../../charts/...`), which claudelint leaves alone, into GitHub
  `blob/main` URLs. Unit tests with `bun test` for the six cases.
- [ ] 2.4 **Links validator.** `starlight-links-validator` (pinned) in the
  Starlight plugins; `errorOnRelativeLinks: false` is **not** set (the
  rewrite must have removed them), `errorOnInvalidHashes: true`. The
  build fails on a dead link; fix the ones it finds (expected: a few in
  historical pages) and list them on the task.
- [ ] 2.5 **Mermaid, client-side (OQ1 (b)).** A small remark plugin
  step (in the same in-repo plugin file) turns a ```` ```mermaid ````
  fence into `<pre class="mermaid">…</pre>`, and a Starlight `Head`
  component override loads a pinned `mermaid` ESM build from
  `site/node_modules` (bundled by Astro, not a CDN) that runs
  `mermaid.run()` on page load and re-themes on the theme toggle
  (`startOnLoad: false`, `theme: dark|default` from
  `data-theme`). No browser in the build. All 39 diagrams render in a
  local preview; a diagram with a syntax error shows mermaid's inline
  error box, so 2.4's validator cannot catch it: add `make
  lint-mermaid` running `mmdc`-free validation with `mermaid.parse` in
  a bun script over every fence (mermaid's parser runs in bun with a
  DOM shim via `happy-dom`, already a UI dev dependency), and wire it
  into `lint-docs`. Verify once by breaking one diagram.
- [ ] 2.6 **Admonitions.** The three `!!! note "v1 only"` blocks in
  `migrations.md` become blockquotes (`> **1.x only.** ...`), matching
  IMPL-0034 3.7's convention; TechDocs renders a blockquote fine.
- [ ] 2.7 **TOC blocks.** Per OQ2, the remark plugin removes the
  `<!--toc:start-->`…`<!--toc:end-->` region on the Starlight side only
  (Starlight has its own right-hand TOC); the blocks stay in the files
  for TechDocs and GitHub.
- [ ] 2.8 **Markdownlint comments.** `<!-- markdownlint-* -->` HTML
  comments pass through as comments in Starlight; confirm none render as
  text (MDX is not enabled; the collection is `.md` only).

## Open Questions

**OQ1. Mermaid rendering strategy.**

- (a) ✅ recommended: **build-time SVG via `rehype-mermaid`** (`img-svg`,
  chromium in the build); no client JavaScript, diagrams in search and
  print, and a bad diagram fails the build instead of showing an error
  box to readers. Costs a browser install in the `docs` job (~20s
  cached).
- (b) client-side `mermaid.js` through a small Starlight component;
  lighter build, no validation, flashes on load, not indexed.
- other:

**Decision (2026-10-25):** (b).

**OQ2. The docz TOC blocks.**

- (a) ✅ recommended: **strip them on the Starlight side in the remark
  plugin**; the files keep their blocks for TechDocs and GitHub, and
  Starlight's own right-hand TOC replaces them.
- (b) delete the blocks from the files and turn off docz TOC
  generation; one fewer transform, but TechDocs loses its in-page TOC
  and 80 files churn.
- other:

**Decision (2026-10-25):** (a).

**OQ3. docz `README.md` → directory landing.**

- (a) ✅ recommended: **map the slug in the loader** (`README.md` →
  `<dir>`), so docz keeps regenerating the READMEs untouched and the
  link plugin has one rule.
- (b) `slug:` frontmatter in each README; docz would need to preserve it
  through `docz update`, which rewrites the tables but not the
  frontmatter today (verify before choosing).
- other:

**Decision (2026-10-25):** (a). claudelint uses the frontmatter form
(READMEs at `/<type>/readme/` with `sidebar: {order: 0, label:
Overview}`, preserved by `docz update`); if `docsLoader()` exposes no
slug hook, fall back to that proven shape in 3.2 without re-opening the
question.

**OQ4. The Historical (1.x) group.**

- (a) ✅ recommended: **hand-list the nine pages in the sidebar config**
  and exclude them from the Operations autogeneration; the files stay
  where their inbound links and TechDocs expect them.
- (b) move them to `docs/historical/` and autogenerate; cleaner tree, but
  473 links to re-check and TechDocs nav edits.
- other:

**Decision (2026-10-25):** (a).

**OQ5. Base URL.**

- (a) ✅ recommended: **`/repo-guardian` on `donaldgifford.github.io`**,
  today's URL; no DNS, existing links keep working.
- (b) a custom domain; needs DNS the project does not own today, and
  every published link changes.
- other:

**Decision (2026-10-25):** (a).

**OQ6. The link rewrite.**

- (a) ✅ recommended: **an in-repo remark plugin** (~80 lines, unit
  tested) handling the `.md` → route mapping, README/index rules and
  out-of-tree links; the rules are ours and the third-party options
  each cover a subset.
- (b) `starlight-auto-links`/`rehype-astro-relative-markdown-links`;
  less code to own, but README mapping and out-of-tree links still need
  a custom step.
- other:

**Decision (2026-10-25):** (a).

**OQ7. Theme approach.**

- (a) ✅ recommended: **Starlight's CSS custom properties only**, set
  from the DESIGN-0036 palette and fonts; no component overrides, so
  Starlight upgrades stay trivial.
- (b) override header/sidebar components to match the UI shell;
  closer match, more to maintain on every Starlight release.
- other:

**Decision (2026-10-25):** (a).
