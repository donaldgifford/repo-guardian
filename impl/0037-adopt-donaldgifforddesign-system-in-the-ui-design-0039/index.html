    Objective

    Move ui/web onto @donaldgifford/design-system 0.3.0: its stylesheet and tokens, its primitives, blocks and shell. Delete the local copies (components/ui, components/charts, the local shell chrome, the @theme in index.css) and the dependencies that only they needed, radix-ui first among them. Ship it as v2.1.0.

    Implements: DESIGN-0039, which rests on INV-0025. Closes issue #252.

    The design's section numbers are cited as "D§n". Its nine open questions are decided and are not reopened here.

    Scope

    In Scope

    • ui/: package.json, bun.lock, .npmrc, Dockerfile, web/, e2e/, scripts/, eslint.config.js, README.md, THIRD_PARTY_NOTICES.md, CHANGELOG.yaml.
    • Build and release wiring for the registry token: Makefile, docker-bake.hcl, .github/workflows/ci.yml, .github/workflows/ghcr.yml, renovate.json5, .github/dependabot.yml.
    • The release bump: charts/repo-guardian/Chart.yaml and the chart tests that pin appVersion.
    • Documents: CLAUDE.md, docs/usage/ui.md and its screenshot, a superseded note on DESIGN-0036, the docz statuses.

    Out of Scope

    • ui/server, the Go code, the API contract, chart templates and values.
    • New pages, panels, columns or filters; a light theme; a change of icon set.
    • Changes to the package. A gap found here is an issue on donaldgifford/design-system (see OQ3).
    • The shared Renovate preset (renovate-config#18). This plan does not wait for it.
    • ecr.yml: it builds no UI image.

    Implementation Phases

    Each phase builds on the previous one. A phase is complete when all its tasks are checked off and its success criteria are met. The phases are the design's seven stages plus the release; they land as commits on one branch and one pull request. make lint-ui, make test-ui and make test-ui-e2e pass at the end of every phase, so a regression belongs to one phase.

    Rules that hold throughout:

    • A task marked deferred - human required is the maintainer's; work continues past it.
    • A visual baseline is regenerated in Phase 2 (colour, if needed) and Phase 6 (the frame) and nowhere else.
    • A changed e2e selector is run against the pre-change build first, to show it can fail.
    • Something wrong in the package is handled per OQ3, never by restyling or patching its internals here.

    Phase 1: Install and auth

    The package is installable everywhere this repository installs, and nothing imports it yet. The app is byte-for-byte the same afterwards. This phase goes first because every later phase depends on CI and the image build being able to fetch the package (D§2).

    Open Questions

    Answer with a letter, or write under other. Option (a) is the recommendation in each.

    OQ1: How do the documents reach main before the work starts?

    INV-0025 is on docs/inv-design-system-migration (pushed); DESIGN-0039, the mockup and this plan are on docs/design-design-system-migration, stacked on it (not yet committed).

    • (a) ✅ recommended: one documents pull request from the stacked branch, containing all four, labelled dont-release, merged before the implementation branch is cut. One review, and the design is accepted with its mockup as the standing rule asks.
    • (b) Two pull requests, the investigation first and then design, mockup and plan. Keeps the investigation's history separate for one more merge.
    • (c) No documents pull request: carry them in the implementation pull request. One merge in total, but the work would start from an unaccepted design and the release PR would carry 1,000 lines of documents.
    • other:

    Decision: (a), 2026-11-17. One dont-release documents pull request from the stacked branch, merged before feat/ui-design-system is cut.

    OQ2: What are the secrets called, and what if CI's GITHUB_TOKEN is refused?

    Renovate and Dependabot each need a maintainer-created token with read:packages (a classic token; fine-grained tokens do not cover packages). CI should work with GITHUB_TOKEN, which task 1.8 proves.

    • (a) ✅ recommended: one classic token stored under the name GH_PACKAGES_READ_TOKEN in three places: Renovate's secrets, Dependabot's secrets, and, only if 1.8 fails, Actions secrets for the ui and ui-e2e jobs. One name to remember and rotate.
    • (b) Separate tokens per consumer with distinct names. Narrower blast radius on a leak, three things to rotate.
    • (c) Skip the bots' secrets for now; do only the CI fallback if needed. Nothing to create today, and the pin is bumped by hand until renovate-config#18 lands.
    • other:

    Decision: (a), 2026-11-17. One classic read:packages token named GH_PACKAGES_READ_TOKEN, for Renovate and Dependabot, and for Actions only if task 1.8 shows GITHUB_TOKEN is refused.

    OQ3: What happens when a package problem appears mid-plan?

    • (a) ✅ recommended: file it on donaldgifford/design-system, keep the affected local file for now, continue with the other phases, and take the fixed 0.3.x before Phase 7. The pull request does not merge with a local workaround in place.
    • (b) Allow a temporary local shim marked with a HACK comment naming the upstream issue, and merge with it. Never blocks on upstream; leaves exactly the kind of patch the design rules out.
    • (c) Stop the plan until the fix is published. Simplest to reason about, idle time on every finding.
    • other:

    Decision: (a), 2026-11-17. File upstream, keep the local file, continue, take the fixed 0.3.x before Phase 7. No merge with a workaround in place.

    OQ4: How is sorting turned off on the embedded tables?

    DESIGN-0039 decided embedded tables do not sort. The package sorts a plain table by default and offers no table-level switch.

    • (a) ✅ recommended: a small local helper beside the views that wraps dataTableColumns<T>() and sets enableSorting: false on every column it builds. One place, no upstream wait, easy to remove if a table should sort later.
    • (b) Ask upstream for a table-level sortable prop and wait for it. The cleanest call site; upstream chose inference over a prop once already (design-system#11), and it blocks Phase 5.
    • (c) Write every embedded column as a display column. No helper, and it loses accessor typing on about 60 columns.
    • other:

    Decision: (a), 2026-11-17, then superseded the same day by (b): upstream published 0.3.0 with sortable on DataTable (design-system#11). The plan pins 0.3.0, the embedded tables pass sortable={false}, and no local helper is written.

    OQ5: What does the chart version become?

    appVersion goes to 2.1.0. The chart's version is independent, and the chart must be republished to carry the new appVersion. Chart templates and values do not change.

    • (a) ✅ recommended: 2.1.0. The chart has tracked the app's version since 2.0.0, and one number is easier for an operator.
    • (b) 2.0.1. Says truthfully that the chart itself did not change, and lets chart and app versions drift apart from here.
    • other:

    Decision: (a), 2026-11-17. Chart version 2.1.0.
